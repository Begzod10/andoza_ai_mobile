# Localization (l10n)

This app uses Flutter's official localization stack: `flutter_localizations`
(SDK) + `intl`, with strings defined in ARB files and a generated
`AppLocalizations` class.

Three locales ship: **Uzbek (`uz`, default and template), Russian (`ru`) and
English (`en`)**, each with the same 834 keys. Users switch language in-app
(Profil → Sozlamalar → Til, or the button at the top of the login screen;
`lib/screens/settings/language_picker_sheet.dart`); the choice is kept by
`lib/providers/locale_provider.dart` under the `SharedPreferences` key
`app_locale` and fed to `MaterialApp.router`'s `locale:`. Until the user picks
one, the app follows the phone's language when it is one of the three, else
Uzbek.

The language also reaches the server:
- every API request carries it as `Accept-Language`, so server messages come
  back in it;
- a picked language is saved on the account (`PATCH /auth/me {language}`, by
  `lib/providers/account_language_provider.dart`); until that succeeds it is
  kept as pending (`app_locale_pending`);
- at sign-in, as on the web, a pending choice is saved, otherwise the app takes
  the account's language from `/auth/me`;
- sign-up, Google and Apple sign-in send the app language, so a new account
  starts in it;
- a change registers the push token again, so pushes are written in it;
- the Studio WebView opens with `?lang=`.

## How the setup works

- **`pubspec.yaml`**
  - `flutter_localizations: { sdk: flutter }` and `intl` are dependencies.
  - `flutter: generate: true` turns on codegen from the ARB files.
- **`l10n.yaml`** (repo root) configures codegen:
  - `arb-dir: lib/l10n` — where the ARB files live.
  - `template-arb-file: app_uz.arb` — the source-of-truth template (Uzbek).
  - `output-localization-file: app_localizations.dart`, `output-class: AppLocalizations`.
- **`lib/l10n/app_uz.arb`** — the Uzbek strings (template). Each entry has a key,
  a value, and an `@key` block with a `description`. `app_ru.arb` and `app_en.arb`
  carry the same keys, without the `@key` blocks.
- **Generated code** (Flutter 3.44+ writes it next to the ARB, no synthetic
  package): `lib/l10n/app_localizations.dart` (abstract base + static
  delegates/`supportedLocales`) and one `app_localizations_<locale>.dart` per
  language. Regenerated by `flutter pub get` or `flutter gen-l10n`.
- **Wiring** — `lib/main.dart`'s root `MaterialApp.router` passes
  `AppLocalizations.localizationsDelegates` and `AppLocalizations.supportedLocales`.
  Any widget under it can call `AppLocalizations.of(context)!`.

Regenerate after editing an ARB:

```bash
flutter gen-l10n
# or simply
flutter pub get
```

## How to add a string

1. Add the key + Uzbek value + `@key` description to `lib/l10n/app_uz.arb`,
   and the same key with its translation to `app_ru.arb` and `app_en.arb`, e.g.:

   ```json
   "actionDelete": "O'chirish",
   "@actionDelete": {
     "description": "Delete. Removes the selected item."
   }
   ```

2. Regenerate (`flutter gen-l10n`).
3. Use it in a widget:

   ```dart
   import '../../l10n/app_localizations.dart';
   // inside build():
   final l10n = AppLocalizations.of(context)!;
   Text(l10n.actionDelete);
   ```

Conventions used here: `action*` for buttons/verbs, `nav*` for tab labels, and a
screen prefix (`login*`, `b1*`, …) for screen-specific strings.

## State of the migration

64 of the 69 files under `lib/screens/` read their strings from `AppLocalizations`.
The five that do not need none: `studio/studio_redirect_view.dart` and the
`c1`, `c8`, `d1` screens only redirect to the web Studio, and
`settings/language_picker_sheet.dart` names each language in that language.
A new screen uses `final l10n = AppLocalizations.of(context)!;` at the top of
`build` from the start; strings in callbacks call `AppLocalizations.of(context)!.<key>`
there. `static const` strings cannot call `.of(context)` and have to be resolved
with a `BuildContext` instead.

### Widget tests

Any test that pumps a migrated screen must give its `MaterialApp` the delegates,
otherwise `AppLocalizations.of(context)` is null. See
`test/widget/login_smoke_test.dart`:

```dart
MaterialApp(
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  supportedLocales: AppLocalizations.supportedLocales,
  home: LoginScreen(),
)
```

## Adding a language

1. Copy `lib/l10n/app_uz.arb` to `lib/l10n/app_<code>.arb`, set `"@@locale"`,
   translate every value, keep the same keys, drop the `@key` blocks.
2. `flutter gen-l10n` — `supportedLocales` picks it up and
   `app_localizations_<code>.dart` is generated.
3. Add the language to `language_picker_sheet.dart` so users can choose it.

If a key is missing from a non-template ARB, codegen warns and falls back to the
template value.
