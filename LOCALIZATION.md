# Localization (l10n)

This app uses Flutter's official localization stack: `flutter_localizations`
(SDK) + `intl`, with strings defined in ARB files and a generated
`AppLocalizations` class.

Uzbek (`uz`) is the default and currently the only locale. The infrastructure
is in place so more strings and additional locales can be added incrementally —
you do **not** need to migrate the whole app at once.

## How the setup works

- **`pubspec.yaml`**
  - `flutter_localizations: { sdk: flutter }` and `intl` are dependencies.
  - `flutter: generate: true` turns on codegen from the ARB files.
- **`l10n.yaml`** (repo root) configures codegen:
  - `arb-dir: lib/l10n` — where the ARB files live.
  - `template-arb-file: app_uz.arb` — the source-of-truth template (Uzbek).
  - `output-localization-file: app_localizations.dart`, `output-class: AppLocalizations`.
- **`lib/l10n/app_uz.arb`** — the Uzbek strings. Each entry has a key, a value,
  and an `@key` block with a `description`.
- **Generated code** (Flutter 3.44+ writes it next to the ARB, no synthetic
  package): `lib/l10n/app_localizations.dart` (abstract base + static
  delegates/`supportedLocales`) and `lib/l10n/app_localizations_uz.dart` (the
  `uz` implementation). Regenerated by `flutter pub get` or `flutter gen-l10n`.
- **Wiring** — `lib/main.dart`'s root `MaterialApp.router` passes
  `AppLocalizations.localizationsDelegates` and `AppLocalizations.supportedLocales`.
  Any widget under it can call `AppLocalizations.of(context)!`.

Regenerate after editing an ARB:

```bash
/home/rimefara/flutter/bin/flutter gen-l10n
# or simply
/home/rimefara/flutter/bin/flutter pub get
```

## How to add a string

1. Add the key + Uzbek value + `@key` description to `lib/l10n/app_uz.arb`,
   e.g.:

   ```json
   "actionDelete": "O'chirish",
   "@actionDelete": {
     "description": "Delete. Removes the selected item."
   }
   ```

2. Regenerate (`flutter gen-l10n`).
3. Use it in a widget:

   ```dart
   import '../../l10n/app_localizations.dart';
   // inside build():
   final l10n = AppLocalizations.of(context)!;
   Text(l10n.actionDelete);
   ```

Conventions used here: `action*` for buttons/verbs, `nav*` for tab labels, and a
screen prefix (`login*`, `b1*`, …) for screen-specific strings.

## Migrating a hardcoded screen (reference pattern)

Two screens are fully migrated as the reference:

- `lib/screens/auth/login_screen.dart` (login)
- `lib/screens/design/b1_room_intro_screen.dart` (B1 room-condition wizard step)

Pattern: import `app_localizations.dart`, grab `final l10n =
AppLocalizations.of(context)!;` at the top of `build`, and replace each string
literal with an `l10n.<key>`. For strings shown outside `build` (e.g. a snackbar
in a callback), call `AppLocalizations.of(context)!.<key>` there directly.

> Note: string literals that are `static const` (e.g. the bottom-nav tab list in
> `app_shell.dart`, or the error-message constants in
> `lib/utils/error_mapper.dart`) can't call `.of(context)` inline — they must be
> refactored to be resolved with a `BuildContext` before they can use `l10n`.
> Keys for these (`navHome/navShop/navMasters/navProfile`, and the common action
> labels) are already seeded in the ARB for when they're migrated.

### Widget tests

Any test that pumps a migrated screen must give its `MaterialApp` the delegates,
otherwise `AppLocalizations.of(context)` is null. See
`test/widget/login_smoke_test.dart`:

```dart
MaterialApp(
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  supportedLocales: AppLocalizations.supportedLocales,
  home: LoginScreen(),
)
```

## How to add a second locale (e.g. Russian) later

1. Copy `lib/l10n/app_uz.arb` to `lib/l10n/app_ru.arb`.
2. Set `"@@locale": "ru"` and translate every value. Keep the same keys; drop
   the `@key` description blocks (only the template needs them).
3. `flutter gen-l10n` — `supportedLocales` will now include `ru`, and a
   `app_localizations_ru.dart` is generated automatically. No other code changes
   are needed; Flutter picks the locale from the device settings.
4. (Optional) To let users switch locale in-app, hoist `MaterialApp.router`'s
   `locale:` to a provider and set it from a settings screen.

Run `flutter gen-l10n` after adding any locale; if a key is missing from a
non-template ARB, codegen warns and falls back to the template value.
